# Bevel engine: straight-skeleton integration

## Multi-way vertex patches and grid boundary flow (2026-10-26)

Flat halfspace strip clipping alone is insufficient at a selected vertex of degree three or greater: edge planes intersect at a shared point instead of producing the required vertex patch. These selected fans now use the existing straight-skeleton face trajectories and shared vertex-fan strip/corner builder, also at Subdivisions 0. Three meeting cube edges therefore yield three strips and one triangular corner, matching the one-segment limit of the rounded construction. Existing single-edge and two-edge shared-miter clipping is retained; this does not add a new kernel, proximity weld or post-publication cleanup. Compatibility event/width limits remain.

For rounded Uniform/Grid junctions, each sampled boundary point carries the actual adjoining strip ruling. First interior grid points continue that ruling; the first cell intersects its two incident rulings when a positive, nonparallel, coincident intersection exists within construction precision. Per-point directions are shared across sectors, and a one-cell even-step junction accepts a new common center only if all sector constraints agree. Skew/incompatible constraints retain the previous shared surface construction. This fixes discrete first-row alignment on the tested orthogonal/nonuniform/rotated cube family; it is not a proof of arbitrary-fan C1 continuity, exact fillets or higher-order fairness. Later interior rows retain the established Coons/radial construction. Cap junctions have no grid rows and are unchanged.

## Straight skeleton and medial axis: responsibilities and limits

Straight-skeleton fronts are offset supporting lines. Adjacent fronts meet along angle bisectors (weighted bisectors for unequal speeds). The medial axis instead measures distance to finite boundary features. For convex polygons these constructions coincide; they differ at reflex features. The medial axis is a candidate for distance/clearance analysis, but is not currently implemented. Neither a medial axis nor independent 2D skeletons alone define the complete 3D strip and vertex-fan topology. CGAL documents these distinctions and the edge-collapse/reflex collision events: https://doc.cgal.org/latest/Straight_skeleton_2/index.html .

A per-face 2D skeleton is insufficient by itself for a selected-edge bevel on a 3D mesh. Adjacent face charts must agree on shared boundary subdivision, source vertex ownership and junction connectivity. Running a whole-solid 3D skeleton is a separate problem: general nonconvex polyhedra have ambiguity and substantially different complexity. Reference: https://arxiv.org/abs/0805.0022 .

Blender's public BMesh implementation demonstrates separate offset intersections, vertex-fan boundary construction, width adjustment, collision limiting and profile/junction construction. These support the architectural separation; its GPL code was not copied: https://github.com/blender/blender/blob/main/source/blender/bmesh/tools/bmesh_bevel.cc .

## Reused implementation and local extensions

Source: https://github.com/Briganti-Games/Straight-Skeleton-Generator . MIT copyright and permission notice are retained alongside the vendored files. Only the wavefront geometry dependencies are included, under an isolated Editor namespace. The source is compiled directly into the Studio Editor assembly; no new runtime assembly or per-frame service is created. Unity.Mathematics 1.3.3 is now an explicit SDK package dependency and Editor assembly reference.

The upstream kernel supplies graph construction and collision-event analysis. Studio adds per-boundary speeds, including zero for unselected boundaries. Corner velocity solves the two moving-line constraints `n0 dot v = speed0` and `n1 dot v = speed1`. With equal unit speeds this recovers the unweighted angle bisector. Relative corner motion handles collapse into stationary corners. Reflex-to-edge timing uses the target edge's speed. These extensions are documented in ThirdParty/BrigantiStraightSkeleton/UPSTREAM.md.

The integration consumes the initial event interval and caches resulting 3D trajectories. It does not construct a complete skeleton graph to extinction. Floating-point positions/predicates remain; this is not an exact-arithmetic kernel. Normalizing each face chart reduces dependency on mesh units. Degenerate or incompatible parallel constraints produce an explicit failure instead of an arbitrary displacement.

## Evaluation pipeline

1. Capture immutable editable polygon topology and geometric adjacency. Keep render triangulation separate.
2. Assign fractional offset budgets consistently within each connected selected-edge region.
3. Build planar face charts and weighted wavefront graphs. Cache corner velocities and the earliest event.
4. Evaluate mesh-local offsets from the captured source. Compatibility construction stops before the first event; eligible clipping construction handles its local clipping events.
5. Preserve distinct intersections belonging to different incident faces. Subdivide retained boundary spans at every shared cut to avoid T junctions.
6. Reuse strip/profile and corner-junction generation, interpolate source attributes, then atomically validate and publish through the existing MeshData preview path.

Width drags do not recompute graphs. The shared one-shot EditorApplication.update scheduler, source restoration, bounded grouped Undo, pane shortcut shield and post-commit bevel selection clearing remain in place.

## Cached local clipping for flat bevels (2026-10-25)

Implemented: flat bevels and eligible subdivided strips share local supporting-halfspace clipping topology where the captured patch satisfies its geometric domain. The MIT straight-skeleton kernel still supplies face-plane trajectories and the first-event width budget. Each affected polygon is clipped against the selected-edge bevel planes, shared edge intersections have one identity, and cap loops are reconstructed from oriented boundary edges. Shared double-precision miter-gradient constraints synchronize two selected strips across every stationary edge of their fan; supporting-plane feasibility and per-component width budgets are checked before applying them. See the corrected junction-reference section below. This supersedes the earlier terminal-patch repair for eligible flat cases. No node system, modifier stack, new preference, menu or shortcut was added.

The method adapts the halfspace clipping principle of Sutherland and Hodgman, Reentrant polygon clipping, CACM 17(1), 32-42 (1974), DOI https://doi.org/10.1145/360767.360802 . The citation establishes the clipping primitive, not a published complete mesh-bevel algorithm or universal industry standard. No third-party implementation was copied. Existing straight-skeleton attribution remains intact.

Capture caches local point provenance, plane classifications and ordered intersection calculations. Width edits reuse them until a clipping classification or Float publication identity changes; only then is affected clipping topology regenerated from the captured source. Convex authored polygon loops stay polygons. Temporary render triangles needed for concave input are recombined only within their original editable face or generated plane identity. Genuine authored triangle edges, material boundaries and attribute seams are retained. Construction does not use proximity welding, thin-face deletion or retrying smaller widths. Existing publication, GPU mirror, cancellation and StudioUndo paths remain in use.

Sampling now uses the captured render-triangle membership, exact source-vertex matches and double dot products. Geometric face normals accumulate in double precision. A certified near-planar n-gon may have distinct Float vertices project to the same 2D point: render triangulation handles that weak projection without deleting editable corners or edges; authored triangles are unchanged. This is render triangulation handling, not permission to hide invalid topology.

Scope: eligible rounded strips share clipping topology and cached cross-section profiles; other rounded layouts retain the compatibility construction. Unsupported open, non-supporting, incompatible collinear-attribute or excessive clipping-work domains retain the existing compatibility path. Local clipping does not complete arbitrary nonconvex 3D collision continuation, global self-intersection resolution or a universal bevel-engine replacement. ## Shared subdivided bevel construction and model-unit width (2026-10-26)

Implemented in the actual SDK: eligible rounded strips now use the same clipped junction topology as flat bevels. StudioMeshCuts.BevelClipProfiles.cs classifies rails and cross-sections from original face/edge incidence. A shared cross-section has one original-corner control and one sampled vertex sequence reused by both strips and terminal source-face boundaries. Each strip lofts those matched profiles into authored quads. This replaces the old independent profile/junction construction for the reported two-pass connected-edge sequence, in either operation order, with Grid or Cap. No wire-edge suppression, finished-mesh weld, deletion of narrow faces, retrying smaller widths or node system is involved. Grid/Cap remain available for genuine multi-way junction patches in the compatibility path; a directly shared two-strip profile needs no extra cap patch.

The miter projection now uses a matrix-free conjugate-gradient nullspace solve with a checked double-precision residual. The previous bounded row sweeps could fail to converge on a finely subdivided chain and silently retain unmatched miter planes. Deterministic ordering, supporting-plane feasibility and independent coupled-component budgets remain. Profile coordinates use integer complementary weights and double arithmetic with one Float rounding, so reversing a cross-section gives identical coordinates. Captured profile layouts are reused while clipping topology is unchanged; no whole-scene rebuild or idle repaint loop was added.

Width offset now means mesh-local model units, minimum zero and default 0.1, with no maximum of 1. StudioModelEditor.Bevel.cs removes the field maximum; StudioMeshCuts.Bevel.cs accepts finite nonnegative values; StudioMeshCuts.BevelWavefront.cs propagates unit offsets instead of multiplying by 45% of the shortest incident edge. Existing saved numeric defaults are retained, so their physical result changes under the new distance semantics; personal profiles were not rewritten. These are mesh-local units, not world-space compensation for object scaling. Zero remains a no-op. Clipping is bounded by its actual unaffected-patch interface rather than an unrelated first 2D skeleton event, and reconstructs affected topology when classifications change. Unsupported compatibility construction still stops at its first skeleton/terminal event. No universal collision-free arbitrary-width claim is made. Miter constraints determine junction geometry; the distance check does not imply identical apparent widths at every dihedral angle.
