# Editable modifier history

Fresh FBX imports recover original control-point connectivity and authored polygon boundaries through the installed Autodesk FBX SDK. Unity UV/normal render splits therefore do not become false subdivision boundaries. Matching validates triangle-to-source-polygon incidence, corner identity, coverage and material consistency; ambiguous overlapping shells are rejected rather than position-welded. Triangle-only sources retain the existing conservative auto-quad conversion. Source mesh assets and importer settings remain unchanged. Mesh-asset and scene-instance imports resolve the source through their original mesh asset path, cached only for that import. Missing SDK, non-FBX or unmatched/ambiguous sources retain the existing raw-index fallback. Existing workspace captures are not migrated: import the source into Studio again. Arbitrary baked transforms and every FBX variant are not established.

Implemented 2026-10-29. The user explicitly chose strict creation order: after Subdivision, new operations edit the denser subdivided geometry. Operations are never silently moved before Subdivision. Saved-workspace backward compatibility is not required; text workspaces now use version 2.

## Workflow

Channels contains a collapsible **Modifiers** group with an icon and the same header styling as Transform. Clear History always appears first inside the group (disabled when empty), followed by applied operations displayed newest first; evaluation remains in creation order. Each operation has a foldout and delete button, without a generic Enabled toggle or explanatory mini text. Actual dependency failure messages remain visible. The group expansion preference uses StudioPreferenceStore. Bevel width/profile/segments/junction/edge-flow, Extrude distance/inset/together, Bridge divisions/curvature, Soften angle and Edit Edge Flow influence/iterations remain editable after subsequent operations.

**Mesh Display > Add Subdivision** appends a new operation. **Subdivision Preview** retains the factory F3 command identity: it adds Subdivision when none exists, otherwise toggles the last Subdivision operation. Custom bindings and explicit unassignment remain authoritative. Multiple Subdivision operations can be added explicitly. Level defaults to 1, supports 0–6 and is finite polygon refinement, not exact limit evaluation. Selecting and editing after it targets its evaluated polygons. Boundary rules remain distinct from normal smoothing. Studio does not store or author subdivision creases.

**Modify > Clear History**, also at the top of the operation list, keeps the currently evaluated mesh and removes its history. The old Bake Subdivision command key is retained for existing shortcut assignments, but its visible label/action is Clear History. Delete, enable/disable, parameter edits and Clear History use StudioUndo. History belongs to mesh data and changes mirror across shared instances. Duplicates get independent copied history.

## Evaluation and failure behavior

The saved source contains full mesh attributes, authored polygons, geometric identities and normal groups. Bevel, Extrude, Bridge, Merge, Soften, Edge Flow and Subdivision are executable parameterized records. Component transforms record vertex offsets. Existing mesh edits without a parameterized replay adapter (including cuts, target weld and transformed/shift extrusion) are named direct-edit records; they retain their exact input and result and can be disabled or deleted, but do not expose invented editable parameters. Object transforms stay in Transform. Newly generated/combined meshes begin from their own base; this is not a cross-object dependency graph.

Replay works on private meshes and publishes the last valid result. Component-based records compare input polygon/index/geometric-ID topology before using saved selections. Width-only changes with stable topology can replay later operations; changed topology produces a visible failure and blocks downstream evaluation. Direct-edit records additionally require the exact original input geometry, so changing earlier geometry can invalidate them. No automatic component remapping or silent selection reassignment is attempted. Repair the earlier operation, delete the broken operation, or Clear History before adding tools.

Mesh changes use existing live-preview commits and a narrow StudioUndo preparation event to atomically register the document with affected mesh edits. Direct-edit capture is attached only while an edit is pending and coalesces a component gesture; it does not install an idle rendering loop. Tool previews remain reversible and do not create records until committed. Modifier numeric fields use Channels drag sensitivity through the shared DragScope and the same deterministic IntegerScrubber used by Tool Options. Edited values reevaluate the affected mesh; scene objects/camera are not rebuilt for each parameter change. History evaluation currently replays from its source, without a general prefix-cache optimizer. Exact-input direct records can use significant storage on dense meshes.

## GPU subdivision

The original cage-only preview behavior is superseded by strict history ordering. CPU evaluation provides editable finite polygons for downstream operations. If the last evaluated operation is Subdivision, its retained input is evaluated again by the Unity compute shader into the actual renderer's GPU buffer. GPU display buffers persist between redraws and are rebuilt when that history revision changes. If another operation follows, its result owns the editable/rendered mesh. There is no synchronous GPU readback during ordinary editing.

Resource ownership and Modeling-only display remain in StudioModelEditor.Subdivision.cs; mode exit, document rebuild and disposal release buffers and restore the evaluated editable mesh. Windows x64 binary and compute/SM5 requirements remain. Unsupported GPU rendering reports a notification explicitly; the history's CPU evaluated editable result remains visible. OpenSubdiv budget remains 500,000 output polygons per operation. UV0–UV7 dimensions 1–4, colors/materials and explicit geometric connectivity use the existing subdivision/tool paths. FBX Cage exports the history source; Evaluated exports the current result without subdividing twice. All-quad outputs are passed as native quads to the existing exporter; mixed polygons retain existing exporter limitations.
