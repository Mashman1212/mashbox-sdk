# Loft visual sections

Multi Spline Loft automatically creates separate render meshes in Play Mode and in scene builds, including scene AssetBundles. Authoring scenes retain the whole editable loft. No scene migration or manually added component is needed. Scene loading also prepares lofts whose authoring component is disabled.

- **Chunk Length (Visuals / Colliders)** defaults to 50. It uses the same approximate distance along the loft as collider generation, including triangle-centroid assignment; it is not a square world grid or a triangle-clipping operation. Visual sections still generate when collider generation is disabled.
- **Visual Cull Distance** defaults to 150 metres. Unity's CullingGroup measures distance to the surface of each chunk's enclosing world-space sphere. This is conservative: a section can stay visible beyond 150 metres from its centre. The measurement does not depend on field of view or LOD bias.
- The final rendered mesh is partitioned, including UVSpline output, shoulders, material slots, normals, tangents, colours, all eight UV channels, and lightmap indices/offsets. MicroBump visuals are also partitioned. Original colliders remain independent.
- The camera priority is `LoftVisualChunks.CameraOverride`, enabled MainCamera, then an enabled Game camera (prefer screen output, then higher depth). Camera discovery is shared across controllers. With no gameplay camera, visuals stay visible. Projects with split-screen or multiple simultaneous gameplay viewpoints should set a primary camera explicitly; this is distance residency around one camera, not a union of multiple viewpoints.
- CullingGroup callbacks change only `forceRenderingOff`; Unity retains per-camera frustum culling. Nearby offscreen meshes can still cast shadows. No LOD simplification or fade is generated.
- Build processing bakes meshes on Unity's temporary scene copy and disables the original visual renderer there. A failed bake fails the build instead of shipping a silently unsplit loft. Both projects must use the updated SDK; an AssetBundle does not ship executable SDK code.
- Play Mode builds temporary meshes after loft regeneration and rebuilds them when the loft or UV output changes. Editor play-state cleanup also handles disabled scene reload. Saved scenes predating the distance snapshot use an approximate centreline-based migration until the loft is next regenerated.

The repeatable `MashBox/Validation/Validate Loft Visual Chunks` check covers geometry/data preservation, material slots, 32-bit indices, collider independence, UV output, culling, missing cameras, and renderer restoration. Run it in an otherwise empty scene so another gameplay camera cannot affect the camera-fallback assertions. An isolated Unity 6000.4.12f1 fixture also verifies actual scene AssetBundle processing and unchanged authoring scene data. Frame-time improvement and visual popping should be profiled on a representative map; 50/150 are starting defaults, not a measured universal optimum.
